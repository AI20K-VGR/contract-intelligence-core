08

How three production systems solve this

Alongside the grading, something more useful: your design next to three systems that already run in production on the same four problems — a production OCR/IDP platform, a structured-extraction engine, and a reasoning-agent platform. The full four-axis comparison, with a column for how far to take it at your scale, is in the reference notes handed out with this review. The headline items:

01

A layer is declared, not inferred from a folder path

And the exemption list is allowed to shrink and nothing else — an entry that no longer reproduces is itself an error, because a stale exemption is a lie about the codebase.

Fixes: your import checker is green because the rule was edited to match the code. Four exemptions, each needing a why, a removal sprint and an owner.

02

Every box declares how it was measured

measured from pixels, derived from another anchor, claimed by a model. The three carry errors that differ by orders of magnitude, and mixing them into one unlabelled list destroys the thing that made the number usable.

Fixes: closes your third bbox level honestly — a clause region is the union of its line boxes, which is derived, and labelling it so is not a weakness.

03

Jobs live in a table, not in the web process

Claimed by a short committed transaction, held by a lease with a fencing token, reclaimed by a reaper. Never hold a row lock across a model call.

Fixes: answers “kill a worker mid-batch” without a message broker. A 40-second vision call holding a database connection will exhaust your pool under any real concurrency.

04

Count how many things “nothing” can mean, then split them

One function returning None for four different facts — not a PDF, a scan with no text layer, a file that would not open, a missing library — is the subtlest bug in any of these systems. Correct for grounding, wrong for completeness: a corrupt file arrives looking like an ordinary scan.

Fixes: your mixed-page routing has exactly this shape today, and silently loses everything inside a scanned overlay.

05

The model enumerates hypotheses; code checks them

At most three, number-free, in one call. Deterministic code then matches each against real evidence and drops what does not resolve. Severity is computed, never asked. Filter first, then cap — capping first biases the sample.

Fixes: this is your own table-continuity pattern applied to conflicts, and it is the main defence against the false-positive flood the brief warns you about.

06

Which pool grounded it sets the trust level — not the model

The model is never asked whether its own claim is well-sourced. And a quote is verified against the source using the same parser that produced it — there is deliberately no second parser, because two parsers disagree eventually.

Fixes: your stored hash is a hash of the model's own output, so it proves nothing about the document. This is the fix.

Three things cannot be grown into the requirement — they will have to be replaced

  1. Background tasks in the web process. Retry, batch state and crash survival are all properties of where the job lives. No amount of code on top fixes it.

11

How this gets checked at the demo

On samples the mentor picks, not the ones you pick.

  • Open a scanned page from your set and draw a word box on the image.
  • Click five values at random; the box must match the text.
  • Show the planted-conflict list, then run the system and show both citations for one of them.
  • Start the whole system with one command.
  • Kill a worker mid-batch; report the job state; run the batch again and show no duplicates.
  • Quote any accuracy number and state its n, its sample, and what it must not be used to claim.
  • Name one number you would not trust, and why. “They are all fine” does not score.

Sample data and ground truth stay out of the repository — that is policy, and you are not penalised for it. The report that carries them still has to exist and still has to reach the mentor.
